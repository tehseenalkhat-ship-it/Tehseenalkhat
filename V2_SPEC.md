## People and power
- Branches: Nairobi (master), Surat, Karachi, Marol, Sidhpur (+ more later). Students ≈700 per branch, only 2–4 teachers per branch → **everything must minimise teacher clicks.**
- **Master admin** (role admin, users.admin_scope='master', Nairobi team): decides courses, levels, steps, logic sets, and global policies; can lock a policy so branches can't change it.
- **Branch admin** (role admin, admin_scope='branch'): changes the *unlocked* policies for their own branch (review counts, print instructions, rubric, bands, merit ratios, officer, nudges…), moderates their branch, sees their branch's insights. Cannot edit courses.
- **Teacher / coordinator**: one shared branch inbox (all teachers of a branch see all their branch's submissions and the full thread history).
- **Student**: sees published courses of their branch.

## Course model (manifest words everywhere in the UI)
Course (Course Code e.g. `FNK-C101`, Pen Type, Course Type, Course Name + Arabic, Description, Branches, Mistar sizes, Drive folder) → Level (`LV01` + Description e.g. مفردات + **Instructions** to students) → Step (`S01` + Task + Type + optional **Message** to students + Max marks + Badge) → Files (role, mistar size, page, version).
Courses without levels (crash, mashq) get one hidden level `LV01`.
**Nothing is fixed by counts**: the sheet may list 130 worksheets but only 30 uploaded — only uploaded/created items exist. **Uploading a file creates its level and step if they don't exist yet.**
Statuses: course `draft|published|held|hidden`; level/step `published|hidden`. Never hard-delete anything students touched — hide/archive.

### Naming convention (parse in `src/v2/lib/naming.ts`, backend-courses owns; frontend-admin copies the pure function to `src/v2/admin/naming.ts` for live preview)
- `CODE_TYPE_LVxx_Sxx_Pxx_SIZE_vN.ext`  e.g. `FNK-C101_MT_LV01_S01_P01_07_v1.jpg`
- Video: `CODE_VD_LVxx_Sxx_vN.mp4`
- Harf: `CODE_HF_LVxx_Sxx_NN_slug_SIZE.png` (NN → page `P{NN}`, slug kept)
- Steps-only courses: `CODE_TYPE_Sxx_Pxx_SIZE_vN.ext` (level = LV01 hidden)
- SIZE ∈ `07,10,20,30,NP` (0.7 mm, 1 mm, 2 mm, 3 mm, Normal pen). Missing version → v1. Case-insensitive; tolerate `-`/spaces around `_`. CODE = `[A-Z]{2,5}-[A-Z]\d{3}`.
- TYPE → step type + file role via the `file_codes` table (MT/PW/WS/HF→worksheet, KT→kitabat, RH→raudat_hidayaat, RS→resource, MS→mashq, AW/AS→assessment (assessment_sheet), IS→istinsakh, FS→final_submission, VD→video, RF→reference attach to the step without changing its type).

### Logic sets (tables `step_types`, `course_types`, `file_codes`, seeded; master can edit/add)
Student behaviour comes from the step type: worksheet/kitabat/raudat/resource/mashq = watch + download + "Mark as done" (no feedback, no marks); istinsakh = upload → teacher feedback + annotation + voice (no marks); assessment = download assessment sheet + upload all worksheets of the level's earlier steps + the assessment sheet → teacher annotates, comments, marks 1–10 → pass gives level badge and opens next level; final_submission = upload → mark → course badge.

### Marking
1–10. Bands from policy `assessment.bands` (default ≤5 revision, 6–8 pass, 9–10 distinction). Revision → student may resubmit (attempts limited by `assessment.max_attempts`). Only the assessment sheet is marked; earlier worksheets show effort. Teacher can give a mark in ONE tap (quick marks on the photo) — empty comment → server picks a warm comment from `review.comment_templates[band]`. AI "refine my comment" button.

### SLA (backend-review)
Unanswered `review.divert_after_hours` (72 h) → reassign to another teacher of the same branch (least loaded, never back to a previous one); if none left → forward to master team (Nairobi). After `review.auto_mark_after_days` (7) with no answer and `review.auto_mark_enabled` → automatic mark = student's own average of previous marks (rounded), else branch average for that step, never below the lowest pass mark; comment = warm template; message shows as from the course team (no "auto" wording to the student); `auto_marked=1` visible only to staff, and a teacher can still review it later and override.

### Merit points (Jamea portal is manual)
Every `merit.levels_per_point` (3) passed levels = 1 point; complete certification = `merit.certification_points` (10). Max `merit.monthly_cap` (10) per student per calendar month (Africa/Nairobi): overflow carries to the next month's pending list (never lost). Points are GIVEN on the Jamea portal by ONE user (`merit.officer_user_id`, per branch; master admins can also act). Admin page "Merit points to give" lists pending for the month; "Mark as given" removes them from the to-do list (status given) and notifies the student; student has a tracker. Reminder to the officer on `merit.reminder_day` and on the last day of the month.

### Downloads & copyright
Every student download of a course file returns a **PDF stamped on the fly** (pdf-lib): small header band with student name, email, TR number, class, branch, date (fields from `downloads.stamp_fields`), the watermark image (`downloads.watermark`, subtle, default centre at 8% opacity) and a footer copyright line (`downloads.copyright_text`). Print-many: select several worksheets → one merged stamped PDF. Show `print.instructions` near every download/print button. Staff downloads are unstamped originals.

### Bulk print → rescan → auto return (teacher time saver)
Teacher selects many submissions → **print pack** PDF: each submission's assessment sheet (or all files) with a header (student name, step) and a **QR code `KHAT:<printCode>:<page>`** plus the readable printCode. Teacher corrects on paper, scans all pages (one PDF or many images) → **scan return** screen decodes QR codes in the browser (pdfjs from `react-pdf`'s `pdfjs-dist` + `jsqr`), groups pages per submission, shows a one-screen list (student, thumbnails, quick-mark buttons, optional comment, AI refine) → "Send all" → each student's thread receives the corrected pages (+ mark). Unreadable pages: teacher types the printCode or picks the student from a list.

### Threads ("WhatsApp" environment)
One thread per (student, step) for upload steps; every upload, mark, annotation, voice note and comment appears in that thread on the same page as the step. Staff see the same thread from the inbox. Unread counts both sides. Emails: student emailed on every staff reply (`email.student_on_reply`); staff get a daily digest (`email.staff_mode`).

### Annotation (critical — calligraphy is taught in person)
Finger / Apple Pencil / mouse on iPad, iPhone and desktop: pen, highlighter, circle, arrow, eraser, undo/redo, colours, pinch-zoom + pan (two fingers), `touch-action:none`. **Long-press (≈500 ms) or right-click anywhere → numbered pin → record a voice note (MediaRecorder) or type a note for that spot.** Student sees strokes + numbered pins; tapping a pin plays its voice note. Store vectors normalised 0..1 + a flattened PNG (upload via `uploadFile('annotations', file)`). Quick marks bar on the same screen.

### Insights + communities
Student segments (doing_well, needs_encouragement, needs_push, dormant, new) with plain-words reason; nudges (manual bulk message + email; automatic for dormant ≥ `nudge.dormant_days`, at most once per 30 days); team self-assessment (reviews by whom, share %, avg response hours, waiting time, overdue, diverted, auto-marked) per branch and per teacher. Communities = staff-created student groups (delegation / special cohorts) with a simple group chat.

### Competitions & calls
`competitions.kind` competition|call (call = "call for calligraphers", e.g. excerpts for decoration), `branch_ids` scope (null = all), `excerpts` (texts/images to write). Results: staff select entries with a label (Winner, Selected for decoration, Honourable mention…) and rank → each selection: notification to the student, highlight on dashboards of that branch, and (tick) published to the gallery as a showcase post (`source='competition'`, award_label). Students can "Request to showcase" any of their passed work in one tap → pending moderation (branch admin or master).

## ADDENDUM — Teacher workload: checking threshold + spill-over network (added 12:35)
Owner's words: "the spill over will be 1) teacher checking threshold setting 2) teacher workload autonomy to spill over from each teacher to other teacher, an option to make a web and network."
- Each teacher has a **threshold** (max open items at once, `users.entry_load_threshold`), an optional **away until** date, and an ordered **spill-over list** (`reviewer_spillover`: teacher → targets, priority 1..n; targets may be in other branches). Together these form a network/web.
- **Who may edit:** a teacher edits his own threshold, away date and spill-over list (targets within his branch, or other branches if a master admin allowed cross-branch by creating the link — keep it simple: teachers can pick same-branch targets; branch admins any teacher of their branch for their branch's teachers; master admins anything incl. cross-branch links).
- **Assignment (backend-review, `reviewLogic.ts`):** new submission → least-loaded *available* teacher of the student's branch. If none available (all at threshold or away) → follow the spill-over lists of that branch's teachers (priority order, breadth-first through the web, skipping visited/unavailable, any branch) to the first available reviewer → if still none, least-loaded teacher of the branch anyway (never block a student). 72 h divert → next hop = the current teacher's spill-over list first, then other same-branch teachers, then master team; never back to a previous reviewer. Away teacher's open items spill on the next sweep. Pure + unit tested (graph cases: cycles, cross-branch, all full, away).
- **API (backend-review, in `review.routes.ts`):** `GET /v2/review/network?branchId=` [ReviewNetwork] (staff: own branch, master: all; include cross-branch targets/receivers) · `PUT /v2/review/network/:teacherId` [ReviewerSettingsUpdate] → [ReviewerLoad] (permission rules above; audit logged).
- **UI:** frontend-review adds a "My workload" drawer in the inbox (threshold stepper, away-until date, drag-ordered spill-over list with teacher search, live open/threshold meter). frontend-admin adds a "Review network" section/tab in the Policies page: every teacher as a card with load meter + arrows/chips to spill targets (a simple visual web: grouped by branch, lines or "→ name (1), name (2)" chips; no chart library), click a teacher to edit the same settings; highlight teachers who are full, away, or have no spill-over target.
